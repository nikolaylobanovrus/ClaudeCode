# Узкий канал правок nginx

Правка боевого nginx едет сюда, в git, а сервер забирает её тем же
таймером, что и сборку сайта (раз в пять минут). Запускать что-либо руками
на сервере больше не нужно.

## Почему не «скопировать конфиг целиком»

Боевой файл `/etc/nginx/sites-available/nalog-servis` уже не равен тому,
что лежит в репозитории: certbot дописал в него 443-й блок с путями к
сертификатам. Копирование снесло бы TLS. Поэтому канал возит не файл, а
**точечные правки**: «найти вот этот кусок — заменить вот на этот».

## Почему правки — данные, а не скрипт

Репозиторий ПУБЛИЧНЫЙ. Если бы сервер выполнял присланный из него скрипт,
любая запись в ветку означала бы выполнение кода на боевой машине. Поэтому
сервер исполняет только свой, установленный однажды вручную
`nalog-servis-pull.sh`, а отсюда получает **описание** правки в JSON,
которое тот интерпретирует. Расширить набор действий через этот канал
нельзя — только найти/заменить в одном файле.

## Формат

Один файл — одна правка. Имя: `NNN-короткое-имя.json`, порядок применения
по имени.

```json
{
  "id": "010-x-frame-options",
  "why": "зачем правка — попадёт в лог сервера",
  "done_marker": "строка, по которой видно, что правка УЖЕ применена",
  "find": "кусок файла, который заменяем (точно, с отступами)",
  "expect": 1,
  "replace": "на что заменяем"
}
```

- `done_marker` делает правку идемпотентной: нашли — пропустили;
- `expect` — сколько раз `find` обязан встретиться (обычно 1). Не сошлось —
  правка не применяется вовсе, и это ошибка, а не «ну и ладно»;
- все правки применяются одной транзакцией: сначала к копии файла, потом
  `nginx -t`, затем перезагрузка и проверка живых адресов. Любой сбой —
  откат к резервной копии.

## Что через этот канал нельзя

Применятель отказывается ставить правку, в которой есть `ssl_certificate`,
`proxy_pass`, `server_name`, `listen`, `include`, `alias`, `root` или
`return` с чужим доменом: TLS, маршрутизация и соседний проект на этом же
сервере каналом не управляются. Это и есть «узкий» — починить кэш, заголовки
или `try_files` можно, увести сайт на другой сервер нельзя.

## Как убедиться, что доехало

Сервер пишет `/var/www/nalog-servis/deploy-status.json` — какая сборка
разложена, какие правки применены и чем кончилось. Он открыт по адресу
`https://налог-сервис.рф/deploy-status.json`, в нём только хеш коммита,
время и результат.

## Когда правка уже на боевом

Правку, которая давно применена, можно свернуть: вписать её прямо в
`deploy/nginx-nalog-servis.conf` (эталон для чистой установки) и удалить
файл из `nginx.d/`. На работающем сервере от этого ничего не изменится —
правка там уже стоит, а канал просто перестанет её возить.
