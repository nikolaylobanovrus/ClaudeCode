# Тест «под ключ» на старом сайте nalog-service.online

Создано 07.09.2026 по запросу владельца: отдельные кампании Директа на услугу
«заполним за вас», посадочная — старый сайт `nalog-service.online`. Через месяц
сравним со страницей «под ключ» на новом сайте.

## Бенчмарк: как старый сайт продавал раньше

В аккаунте Директа лежат 40 архивных кампаний 2022 года на этот же сайт
(«13. Налог-сервис| Поиск| Ключевая: помощь вычет» и т. д.). Они крутились до
июня 2026 и выключены с переездом на новый сайт. Их данные — готовая точка
отсчёта для теста (счётчик 89630324, атрибуция LSCCD, 07.2025–07.2026):

| Показатель | Значение |
|---|---|
| Клики | 14 399 |
| Расход | 58 567 ₽ |
| Средняя цена клика | 4,1 ₽ |
| Заявок (цель «контактные данные отправлены», 339285326) | 181 |
| Автоцель «отправка формы» (252757417) | 184 |
| Цена заявки | ~324 ₽ |
| Конверсия визита в заявку | ~1,3 % |

Главный вывод: **92 % кликов и 97 % заявок принесли не фразы, а
автотаргетинг** (13 212 кликов, 175 заявок, 307 ₽/заявка). Свои фразы
(«помощь в получении вычета» и т. п.) давали единичные клики. Запросы,
с которых шли заявки, — информационные: «как получить налоговый вычет»,
«как вернуть вычет за лечение зубов», «налоговый вычет за 2025 год за ипотеку».
То есть форма «оставьте заявку — перезвоним» ловила тех, кто ещё только
разбирается. Это противоположно нашей анкете за 199 ₽, где информационный
трафик не покупает.

Сколько из 181 заявки стали оплатами — в Метрике нет, знает только владелец.
Для сравнения с новым сайтом нужен именно этот показатель.

## Пересечения с основной кампанией

В группе `02_Общие_цена-помощь` основной кампании есть 9 «услужных» фраз
(«заказать декларацию 3 ндфл», «помощь +в заполнении 3 ндфл», «сколько стоит
заполнить 3 ндфл» и т. д.), которые теперь дублируются в новой. Внутри одного
аккаунта Яндекс показывает по запросу одно объявление — то, у которого выше
ставка × прогноз CTR, — поэтому трафик по этим фразам разделится непредсказуемо.
07.09 по решению владельца остановлены (`keywords.suspend`) 10 фраз группы 02,
совпадающих с новой кампанией после нормализации: «сколько стоит заполнить
3 ндфл», «сколько стоит заполнение декларации 3 ндфл», «заполнение 3 ндфл
цена», «заполнение декларации 3 ндфл стоимость», «помощь +в заполнении 3 ндфл
-декларация», «помощь +в заполнении декларации 3 ндфл», «заказать декларацию
3 ндфл», «заказать заполнение 3 ндфл», «услуги +по заполнению 3 ндфл»,
«стоимость декларации 3 ндфл». В группе остались 7 фраз про «услугу» и
автотаргетинг. Вернуть по окончании теста: `keywords.resume` по тем же id
(57644590673–57644590681, 57818309433).

## Как читать результат через месяц

Считаем по счётчику 89630324, срез `utm_campaign` = 714198176 / 714198177:
визиты, заявки (339285326 + 252757417 без двойного счёта — брать визиты
с достигнутой целью), расход из Директа, и **число оплат** от владельца.
Сравниваем с новым сайтом: там та же услуга ловится целью `turnkey_lead` и
формой на `/#/pod-klyuch`. Критерий — цена оплаченного заказа, не цена заявки.

   На новом сайте 3/2/1. Пункт 8 нашей оферты тоже говорит «5 рабочих дней» —
   расхождение и у нас, править обе стороны.

   Какой верный — уточнить у владельца.
4. Уведомление о cookies называет исполнителя «ООО «Налог-сервис»», юрлицо —
   ООО «Информкарт».
5. Контакты: WhatsApp/Telegram +7 912 791-64-70 рядом с +7 920 837-91-93.
   Какой номер живой — уточнить.
6. Мёртвый Google Analytics UA-208621522-1 (UA выключен с 2023) — убрать.
7. Кнопка предоплаты ЮKassa и попап Marquiz — оставлять ли, решает владелец.

Технически сайт — собранный Vue-бандл (`/js/app.bc237cf3.js`, `/js/chunk-vendors.*.js`),

приложение с тремя тарифами), `policy.html` (дата), `index.html` (снять gtag,

для быстрых ссылок Директа). Проверка — локально в Playwright на копии сайта,
сверка байтов после загрузки по sha256.

### Доступ

Выбран вариант 1 (07.09): архив + инструкция в `old-site/README.md`,
патч воспроизводится скриптом `old-site/patch.py`. Ответы владельца: ИНН
7420010847, КПП 741501001; живой номер +7 920 837-91-93, мессенджеры только
Telegram и Max; Marquiz остаётся; заявки формы приходят на
nalog-service@internet.ru; форма оплаты ЮKassa в разделе заказа есть
(магазин 836525) — оставлена как была.

Из этой среды наружу ходит только HTTPS через прокси: SSH и FTP Beget
недоступны, залить файлы напрямую я не могу. Варианты, от простого к удобному:

1. **Файловый менеджер Beget** (ничего не выдавать). Я готовлю архив с
   изменёнными файлами и точный список «что куда», владелец загружает.
   Для одного-двух патчей за месяц — достаточно.
2. **Cron с git pull на Beget** — как на VPS. Владелец один раз через SSH или
   раздел «Cron» в панели Beget добавляет задачу раз в 5 минут:
   `cd ~/nalog-service.online/public_html && git pull -q origin deploy/old-site`.
   Дальше я деплою пушем в ветку `deploy/old-site`. Нужен снимок текущего сайта
   в этой ветке (я соберу из того, что уже скачал, плюс css/шрифты).
3. FTP-пользователь, ограниченный папкой сайта, — из песочницы всё равно не
   достучаться, поэтому не подходит.

Пароль от панели Beget и API Beget не нужны и присылать их не надо.
