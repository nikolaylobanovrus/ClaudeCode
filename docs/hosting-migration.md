# Переезд с GitHub Pages на российский хостинг

## Что случилось

17–18 августа 2026 до сайта переставала доезжать примерно **треть**
оплаченного рекламного трафика:

| День | Клики (оплачены) | Визиты в Метрике | Потеряно |
|---|---|---|---|
| 15.08 | 125 | 116 | 7 % |
| 16.08 | 114 | 112 | 2 % |
| 17.08 | 154 | 57 | **63 %** |
| 18.08 | 75 | 25 | **67 %** |

Проверка с телефона владельца:

* через **мобильный интернет** сайт открывается;
* через **проводного провайдера** — «Превышено время ожидания ответа».

Соединение устанавливается, но ответа нет — это фильтрация на стороне
оператора, а не поломка сайта. Домен `налог-сервис.рф` (punycode
`xn----7sbhcltqolxje.xn--p1ai`) A-записями смотрит на GitHub Pages:

```
185.199.108.153  185.199.109.153  185.199.110.153  185.199.111.153
```

Эти адреса у части российских операторов недоступны. Пока сайт лежит на
них, проблема воспроизводится у непредсказуемой доли аудитории.

## Решение

Отдавать статику из **российского объектного хранилища** (S3) и держать
DNS на нём. Сборка не меняется: сайт — статический SPA на hash-роутере,
никакого сервера ему не нужно.

Скрипт выкладки один и тот же для любого S3-совместимого хранилища —
`scripts/deploy-static.py`.

### Вариант 1 — Яндекс Облако (рекомендуемый)

Аккаунт Яндекса уже есть (Директ и Метрика), счета будут в одном месте.

1. `console.yandex.cloud` → создать платёжный аккаунт.
2. Object Storage → создать бакет, имя `nalog-servis`, доступ **публичный
   на чтение**.
3. В настройках бакета → «Веб-сайт»: главная страница `index.html`,
   страница ошибки — тоже `index.html` (SPA: любой путь должен отдавать
   приложение).
4. Сервисные аккаунты → создать аккаунт с ролью `storage.editor` →
   «Создать статический ключ доступа». Сохранить пару.
5. CDN (или сразу бакет) → привязать домен `налог-сервис.рф`, выпустить
   бесплатный TLS-сертификат Let's Encrypt.
6. У регистратора домена заменить A-записи на адреса, которые выдаст
   Яндекс Облако.

Стоимость: хранилище ~5 ₽/мес (сайт весит около 3 МБ), трафик ~1 ₽/ГБ.
При нынешних 150 визитах в день выходит меньше 100 ₽/мес.

### Вариант 2 — Timeweb Cloud S3

Дешевле и проще в интерфейсе, но отдельный аккаунт и отдельная оплата.
Шаги те же: бакет → публичное чтение → ключи → домен → DNS.

### Чего делать НЕ надо

* Ставить перед GitHub Pages зарубежный CDN (Cloudflare) — он и сам
  попадает под ту же фильтрацию.
* Менять hash-роутер на обычный до переезда: сейчас это лишний риск,
  а SEO-выгода появится только после того, как сайт станет стабильно
  доступен.

## После получения ключей

Дописать в `/root/.ndfl-tokens` (файл вне репозитория, права 600):

```
S3_ENDPOINT=https://storage.yandexcloud.net
S3_BUCKET=nalog-servis
S3_KEY_ID=...
S3_SECRET=...
```

Дальше выкладка одной командой:

```
VITE_HASH_ROUTER=1 npm run build && python3 scripts/deploy-static.py
```

Скрипт заливает только изменившиеся файлы (сверяет md5 с ETag), ставит
`no-cache` на `index.html` и вечный кэш на файлы из `assets/` (у них хеш
в имени), и подчищает устаревшие объекты.

## Проверка после переезда

1. `dig налог-сервис.рф` — адреса больше не 185.199.108–111.153.
2. Открыть сайт у того провайдера, где сейчас таймаут.
3. Через сутки сверить в Метрике клики и визиты: `ym:ad:clicks` против
   `ym:ad:visits` должны сойтись (норма — расхождение до 10 %).

Ветка `claude/react-website-wi5fnz` и GitHub Pages какое-то время
остаются как запасная площадка — выключать их стоит только после того,
как новый хостинг отработает без сбоев неделю.
