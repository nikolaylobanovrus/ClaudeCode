# Официальная структура XML-файла 3-НДФЛ (НО_НДФЛ3)

Извлечено из текста приказа ФНС от 19.09.2024 № ЕД-7-11/757@, Приложение N 3
(ВерсФорм 5.19, КНД 1151020). Первичные источники:
- Таблицы формата: https://www.consultant.ru/document/cons_doc_LAW_489471/26342767d862f309c28531b583e3c8a5aa57b8ac/
- Полный текст (все таблицы): https://base.garant.ru/410645900/3e22e51c74db8e0b182fad67b502e640/

Это спецификация для приведения генератора `src/lib/ndfl/xml3ndfl.js` к
официальному дереву. Backbone (корень, «Документ», налогоплательщик,
Раздел 1, Раздел 2, Приложение 1) подтверждён по таблицам формата.
Внутренние поля Приложений 5 и 7 и атрибуты источников дохода в доступных
превью обрезаны — их берут из скачанной XSD-схемы (см. README).

> ВАЖНО: текущий генератор пока формирует XML по СВОЕЙ, неофициальной
> схеме имён (СведНал/ЗаявВозвр/Прил5 и т.п.) — поэтому файл помечен
> «бета». Переписывать вслепую на официальные имена нельзя: часть полей
> (вычетовые приложения) без реальной XSD не сверить. Порядок работы —
> положить схемы (README) → `npm run validate:xml` → чинить по ошибкам
> валидатора → снять «бета».

## Подтверждено (backbone)

```
<Файл ИдФайл="…" ВерсПрог="…" ВерсФорм="5.19">   ← ВерсПрог ОБЯЗАТЕЛЕН (сейчас его нет)
  <Документ КНД="1151020" ДатаДок="ДД.ММ.ГГГГ" Период="34"
            ОтчетГод="ГГГГ" КодНО="0000" НомКорр="0">   ← атрибута «ПоМесту» здесь НЕТ
    <СвНП>
      <НПФЛ3 ДокПредст="…" Статус="1" Тлф="…">
        <ФИОФЛ Фамилия="…" Имя="…" Отчество="…"/>
        <СведФЛ ДатаРожд="ДД.ММ.ГГГГ" ОКСМ="643">
          <УдЛичн …/>            ← сведения о документе, удостоверяющем личность
        </СведФЛ>
        <!-- либо <ИННФЛ>############</ИННФЛ> вместо СведФЛ -->
      </НПФЛ3>
    </СвНП>
    <Подписант ПрПодп="1"/>       ← ОБЯЗАТЕЛЕН; при ПрПодп=2 добавляются ФИО + СвПред
    <НДФЛ3>
      <!-- Раздел 1: обёрток Раздел1/Раздел2 в формате НЕТ.
           СумНалПуИскл227 и НалБаза объявлены unbounded — на этом стоит
           комбинированная декларация (продажа + вычет за один год): два
           блока Раздела 1 с разными КБК и две налоговые базы, «01»
           (зарплата) и «02» (доход от продажи). Возможно с формы 2025
           года; до неё обе суммы лежали в одной базе с кодом «10». -->
      <СумНалПу>
        <!-- КБК зависит от типа декларации, схемой это НЕ проверяется:
             возврат вычета  → 18210102010011000110 (налог удержал агент)
             продажа имущества → 18210102030011000110 (платит сам, ст. 228) -->
        <СумНалПуИскл227 КБК="…" ОКТМО="…" ПодлУпл="0" ПодлВозв="<сумма к возврату>"/>
      </СумНалПу>
      <ЗаявРаспДС Сумма="<сумма>">
        <СвСчБанк БИК="…" ВидСч="02" НомСч="…"/>
      </ЗаявРаспДС>
      <!-- Раздел 2 -->
      <НалБаза ВидДоход="…">
        <РасчНалБаза СумДох="…" СумДохНеНал="0" СумДохНал="…" СумНалВыч="…"
                     СумРасх="0" НалБаза="…" НалБаза2.1.224="…"
                     НалБаза3.1.224="…" СумИное="0"/>
        <РасчНалПУ Исчисл="…" Удерж="…" СумУдержИст224="0" СумУдержМат="0"
                   ТСУплПерЗач="0" СумФиксАван="0" УплИнПодлЗач="0"
                   УплПатентЗач="0" ПодлУпл="0" ПодлВозв="…" СумВозвУпр="0"/>
      </НалБаза>
      <!-- Приложение 1 -->
      <ДоходИстРФ ВидДоход="…" ОКТМО="…" Доход="…" НалУдерж="…">
        <ИстЮЛ …/>                ← атрибуты источника НЕ подтверждены
      </ДоходИстРФ>
      <ВычСтандСоц …/>            ← Приложение 5: имя элемента верно, поля НЕ подтверждены
      <ИмущНалВычНов …/>          ← Приложение 7: имя элемента верно, поля НЕ подтверждены
    </НДФЛ3>
  </Документ>
</Файл>
```

## Соответствие текущего генератора и официальных имён

| Смысл | Сейчас в xml3ndfl.js | Официально (757@) |
|---|---|---|
| Корень | `Файл` (без ВерсПрог) | `Файл` + **ВерсПрог** |
| Документ | `Документ` (+ ПоМесту) | `Документ` (без ПоМесту) |
| Налогоплательщик | `СвНП`→`НПФЛ` | `СвНП`→`НПФЛ3` |
| ФИО | `ФИО` (в НПФЛ) | `ФИОФЛ` (в НПФЛ3) |
| Паспорт/рождение | атрибуты в НПФЛ | `СведФЛ`(ДатаРожд,ОКСМ)→`УдЛичн` |
| Подписант | `Подписант ПрПодп` | `Подписант ПрПодп` ✓ |
| Раздел 1 | `Раздел1`→`СведНал` | `СумНалПу`→`СумНалПуИскл227` |
| Заявление о возврате | `ЗаявВозвр`→`СведСчет` | `ЗаявРаспДС`→`СвСчБанк` |
| Раздел 2 | `Раздел2` (плоский) | `НалБаза`→`РасчНалБаза`+`РасчНалПУ` |
| Приложение 1 | `Прил1`→`ИстДохРФ` | `ДоходИстРФ`→`ИстЮЛ`/`ИстФЛИн` |
| Приложение 5 | `Прил5` | `ВычСтандСоц` (поля не сверены) |
| Приложение 7 | `Прил7` | `ИмущНалВычНов` (поля не сверены) |

## Имя файла обмена

`NO_NDFL3_{КодНО получателя,4}_{КодНО конечного,4}_{ИНН[+КПП] отправителя}_{ГГГГММДД}_{GUID}.xml`
Текущий генератор использует `NO_NDFL3_{ИФНС}_{ИФНС}_{ИНН}_{дата}_{GUID}` — по
структуре совпадает (получатель = конечный получатель = ИФНС клиента,
отправитель-физлицо = 12 знаков ИНН).
