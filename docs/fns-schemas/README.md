# XSD-схемы ФНС для проверки XML-декларации

Здесь лежат официальные XSD-схемы формата 3-НДФЛ (файл обмена НО_НДФЛ3).
С их помощью скрипт `npm run validate:xml` проверяет, что XML, который
формирует сайт, соответствует формату ФНС. Пока схем здесь нет, файл XML
на сайте помечен «бета».

## Почему схемы не в репозитории

Сайт работает в облаке, а сервер форматов ФНС (`format.nalog.ru`,
`data.nalog.ru`) закрывает автоматический доступ (ошибка 403). Поэтому
скачать схемы автоматически из среды разработки нельзя — их нужно один
раз положить сюда вручную из вашей сети.

## Как скачать схемы (5 минут)

1. Откройте страницу форм 3-НДФЛ на сайте ФНС:
   https://www.nalog.gov.ru/rn77/taxation/taxes/ndfl/form_ndfl/
2. Для нужного года откройте приложение «Формат представления… в
   электронной форме» — там будет ZIP-архив со схемой (`.xsd`).
   Прямые имена схем по годам:
   - 2022 → `NO_NDFL3_1_033_00_05_17_xx.xsd` (приказ ЕД-7-11/880@)
   - 2023 → `NO_NDFL3_1_033_00_05_18_xx.xsd` (приказ ЕД-7-11/903@/615@)
   - 2024 → `NO_NDFL3_1_033_00_05_19_xx.xsd` (приказ ЕД-7-11/757@)
   - 2025 → `NO_NDFL3_1_033_00_05_20_xx.xsd` (приказ ЕД-7-11/913@)
   (`xx` — номер версии схемы, берите самый свежий.)
3. Распакуйте архив и положите файлы схемы в эту папку, ПЕРЕИМЕНОВАВ
   главный файл по году — ровно так:
   - `docs/fns-schemas/3ndfl-2022.xsd`
   - `docs/fns-schemas/3ndfl-2023.xsd`
   - `docs/fns-schemas/3ndfl-2024.xsd`
   - `docs/fns-schemas/3ndfl-2025.xsd`
   Вспомогательные файлы (общие типы, справочники — например
   `NO_NDFL3...`, `Common...`), если схема на них ссылается, положите
   рядом БЕЗ переименования — `xmllint` подхватит их по относительным
   путям из главного файла.

Класть можно не все годы сразу — валидатор проверит те, для которых
схема есть, а остальные пропустит.

## Как запустить проверку

```
npm run validate:xml
```

Скрипт сгенерирует тестовую декларацию за каждый год (через тот же код,
что и на сайте) и проверит её через `xmllint --schema`. Вывод — по годам:
`OK` (файл прошёл схему) или список ошибок с номерами строк.

## Как снять пометку «бета»

Когда `npm run validate:xml` показывает `OK` по всем нужным годам —
структура XML соответствует схеме ФНС. После этого в
`src/wizard/steps/StepDocuments.jsx` уберите проп `beta: true` у документа
«Файл для Личного кабинета ФНС» (это одна строка), и бейдж «бета» пропадёт.

Скорее всего валидатор сначала покажет ошибки: текущий генератор
формирует XML по своей схеме имён, а официальные имена элементов другие.
Их полный список и таблица соответствия — в `xml-structure.md` в этой же
папке (структура сверена с приказом ФНС ЕД-7-11/757@). По ошибкам
`xmllint` и этой таблице генератор `src/lib/ndfl/xml3ndfl.js` приводится к
официальному дереву — после чего валидация зеленеет и «бета» снимается.

> Схемы ФНС распространяются как официальные документы; при желании
> добавьте `docs/fns-schemas/*.xsd` в `.gitignore`, если не хотите держать
> их в репозитории — валидацию можно запускать локально.
