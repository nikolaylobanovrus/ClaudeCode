# Восстановление «Авто вычет» — рабочие заметки

Дата фиксации: 2026-11-27

## Рабочая ветка

- Исходная ветка: `claude/tax-deduction-declaration-site-dfit30`
- Ветка восстановления: `recovery/auto-vychet-restoration`
- Исходная ветка сохраняется без изменений. Публикация на домен не выполняется из этой ветки автоматически.

## Подтверждённая архитектура исходного проекта

- Клиентская часть — статическое приложение React + Vite.
- Развёртывание, описанное в `docs/hosting-migration.md`, использует Nginx на Beget и периодическую загрузку готовой сборки из `deploy/nalog-servis-dist`.
- В изученной версии репозитория нет реализации самостоятельной базы данных на Beget. В документации и коде приложения Supabase по-прежнему отвечает за записи клиентов, заказы, заявки, операторскую авторизацию и приватные файлы.
- Черновик анкеты декларации сохраняется в браузере клиента через `localStorage`.
- Кабинет оператора расположен на маршруте `/operator`. Из него можно просматривать клиентов и заявки, работать с приватными файлами, назначать тариф/сумму и переходить к мастеру декларации.
- Для создания декларации оператором предусмотрен отдельный RPC-путь `operator_paid_order`, который создаёт заказ со статусом `paid` и нулевой суммой.
- Платёжные и документные серверные операции вынесены в Supabase Edge Functions. В частности, присутствуют функции создания платежа, вебхука ЮKassa, разбора документов и подсказки адреса.

## Что требует дополнительной сверки

1. Установить, какие изменения после зафиксированной исходной ветки были сделаны на уничтоженном VPS и существовала ли отдельная Beget-реализация базы/API.
2. Сопоставить резервную базу Supabase с реальным рабочим состоянием перед аварией.
3. Сохранить резервную копию базы и отдельно файлы Storage до любых изменений.
4. Получить репозиторий/исходники действующего сайта `nalog-service.online`, чтобы не затронуть сервис «Под ключ» и спроектировать безопасное разделение.
5. Проверить сборку и основные пользовательские сценарии локально до подготовки развёртывания.

## Правила безопасной работы

- Не изменять исходную ветку и не выполнять деплой без отдельного согласования.
- Не применять SQL-миграции и не менять Edge Functions до резервного копирования и сверки с рабочим состоянием.
- Не помещать пароли, API-токены, секреты платёжных провайдеров, персональные данные и содержимое клиентских документов в Git.
- Все изменения приложения вести в этой рабочей ветке, проверять сборку и тесты, после чего предлагать Pull Request.


## Уточнение владельца по сервису «Под ключ» (27.11.2026)

- Восстанавливаемый сайт уже содержит собственную, аналогичную по назначению реализацию сервиса «Под ключ».
- Эта реализация остаётся частью текущего проекта на этапе восстановления и доработки.
- В дальнейшем её планируется доработать и перенести на действующий отдельный сайт `nalog-service.online`, заменив там существующую реализацию целиком.
- Текущий `nalog-service.online` технически не связан с репозиторием `ClaudeCode`; на этапе восстановления он остаётся нетронутым.
- Репозиторий действующего `nalog-service.online` для текущего этапа не требуется.
- Это будущее направление уже отражено в комментарии маршрута `/pod-klyuch` в `src/App.jsx`: там указано решение владельца (июль 2026) о последующем переносе на отдельный домен.
